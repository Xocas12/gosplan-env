Implementation notes

  1. DESIGN. 2,000 episodes each of `Random`, `TruthfulMyopic` and `Padder`, at
     `p1_default_config()` and at 20 random perturbations of SUPPLY parameters - 21 configurations,
     3 agents (the PLAN section 14 cost line). ONE `seed_env` shared by all three agents, so they
     meet common random numbers by construction (sections 2.15, 4.3); it is recorded in every
     manifest and in the report.

  2. PERTURBATIONS. Continuous parameters from `SUPPLY_PERTURBATION_RANGES`, drawn uniformly on the
     PLAN section 3 sweep ranges (`yield_sigma` multiplier [0.5, 2]; `final_demand_share`
     [0.3, 0.7]; `holding_loss` [0, 0.05]); the discrete one from `SUPPLY_PERTURBATION_CHOICES`
     (`input_complementarity` in {2, 8, inf}). The `theta = inf` Leontief `min` branch of section
     2.6 MUST be exercised here: the Phase-1 default of 8.0 never reaches it. Every name in
     `PERTURBATION_EXCLUDED` (`delivery_timing`, `arrival_probs`, `input_holding_loss`, `trade_tau`,
     `alloc_eta_request`) stays at its Phase-1 value - they are the mechanism parameters locked in
     PLAN section 4.2 behind held-out phenomena 2, 5 and 6, and perturbing them here exercises a
     locked mechanism before its pre-registered study exists. Validate every configuration with
     `EnvConfig.validate()` and name it by `EnvConfig.hash()`.

  3. ASSERTIONS - all boundedness and conservation, none directional. Record the observed extreme
     for each rather than stopping at the first failure:
       - the per-period, per-good conservation identity of T-U1 holds to `CONSERVATION_TOL` (1e-9);
       - no NaN and no inf in any ledger column;
       - `T_i` stays inside `[T_min, T_0 * ((1 + g) * (1 + lambda * c_up))**P_max]` - the floor of
         section 2.7.1 and the largest value the capped ratchet can reach in `P_max` periods; BOTH
         ENDPOINTS COMPUTED FROM THE CONFIGURATION, never hard-coded;
       - `S_i` stays inside `[0, inventory_cap_mult * cap_i]` (section 2.11);
       - `fill_i` stays inside `FILL_BOUNDS` = [0, 1] (`claimed = 0` gives `fill = 1` by the WO-006
         convention, so the upper bound is attainable and is not an error);
       - under `Padder`, at least one enterprise sees `fill < 1` in some period - the delivery
         channel of section 2.7.3 propagates a shortage (test T-B3's property; NOT a held-out row);
       - the wall clock per episode is measured, so the PLAN section 14 estimate can be checked
         against reality before Phase 1 commits to it.

  4. REPORT. `runs/mc_sanity/report.md`: one section per configuration and agent, every assertion
     with its observed extreme, the flags raised (BOUND_BINDING among them, rule 8), the per-episode
     wall clock, the configuration hash that names the run directory, and A VERBATIM RESTATEMENT OF
     THE HELD-OUT PROHIBITION this harness ran under (`HELD_OUT_PHENOMENON_ROWS = (2, 5, 6, 7)`).

  5. MANIFESTS. Each configuration writes `runs/<hash>/` through `write_manifest` (rule 10). This
     harness writes no manifest of its own; the report references the hashes.

  6. IMPORTS. `pyarrow`, `pandas` and any plotting dependency are imported inside the function that
     uses them, never at module scope.

  7. EXIT CODE. `main()` returns 0 when every configuration ran and every assertion held. IT NEVER
     MEANS "GATE G0 PASSED": G0 is the lead's written sign-off on this report together with a green
     frozen suite and the rule-7 diff review of `gosplan/env/`.
