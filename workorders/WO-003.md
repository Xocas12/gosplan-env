Implementation notes

  Only four bodies are missing from `gosplan/config.py`. Everything else in that file - the four
  frozen dataclasses, their fields, their Phase-1 defaults and their docstrings - is already correct
  and is not to be touched.

  1. `EnvConfig.validate() -> None`. Checks every cross-field invariant and raises `ValueError` on
     the FIRST violation, with a message naming the offending field and the rule it broke. PLAN
     section 3 and the `validate` docstring in `spec/spec.py` fix the list. It must reject at least:
       - `incentive.overfulfilment_cap < 1`;
       - `incentive.notch_width < 0`;
       - `supply.input_complementarity < 1`;
       - any row `j` of `supply.io_matrix` with `sum_k a[j][k] >= 1` (no self-sustaining sector);
       - negative `ratchet_cap_up`, negative `ratchet_cap_dn`, and negative scales generally
         (`penalty_scale`, `effort_cost`, `notch_height`, `overfulfilment_slope`, the yield sigmas,
         `holding_loss`, `input_holding_loss`, `trade_tau`, `price_markup`).
     Plus the structural checks the docstring lists, implied by PLAN sections 2.1-2.12:
       - `len(sector_of) == n_enterprises`, every entry in `[0, n_sectors)`;
       - `io_matrix` is `n_sectors x n_sectors`; `final_demand_share`, `productivity`,
         `yield_sigma`, `ces_alpha` each have length `n_sectors`;
       - `len(arrival_probs) == steps_per_period`, summing to 1, when
         `delivery_timing != "uniform"`;
       - probabilities in `[0, 1]`: `audit_rate`, `tenure`, `ministry_passthrough`,
         `final_demand_share`, `horizontal_visibility`, `quality_measurability`,
         `shortfall_visibility`, `soft_budget`;
       - `min_periods <= max_periods`; `report_max_ratio > 1`; `invest_lag >= 1`; `ces_sigma > 0`.

  2. `EnvConfig.hash() -> str`. The SHA-256 hex digest of the canonical JSON encoding of the whole
     configuration. Canonical means: keys sorted, so the digest is invariant to field order; floats
     formatted with `repr`; `float("inf")` serialised as the string `"inf"`; tuples encoded as JSON
     arrays. The digest names the run directory `runs/<hash>/` and goes into every manifest
     (CONTRACT rule 10), so it must be stable across processes and platforms - use `hashlib`, never
     Python's builtin `hash`, which is salted per process. Two configurations differing in any
     single parameter must hash differently, including a difference only in `spec_version`.

  3. `load_config(path) -> EnvConfig`. Reads a JSON or TOML document whose top-level keys are
     `supply`, `incentive`, `information`, `tech`, and optionally `spec_version`. Missing keys take
     the Phase-1 defaults already declared on the dataclasses. Decode the string `"inf"` back to
     `float("inf")` - the exact inverse of `hash`'s encoding. Convert every array-valued field to a
     `tuple` (of tuples for `io_matrix`), because the dataclasses are frozen and hashable. Call
     `EnvConfig.validate()` before returning. RAISE `ValueError` ON AN UNKNOWN KEY at any level:
     silently ignoring an unrecognised parameter would let a sweep run at defaults while its
     manifest claimed otherwise, which is the exact failure CONTRACT rule 10 exists to prevent. Use
     `tomllib` from the standard library for TOML; `json` for JSON; select by file extension.

  4. `p1_default_config() -> EnvConfig`. Returns `EnvConfig()` - every field at its declared Phase-1
     default - validated before it is returned. It must agree field by field with the `default` of
     the corresponding `ParamSpec` in `gosplan/params.py`; `tests/unit/test_config.py` asserts that
     agreement, so if the two disagree the fix is a spec/registry question and an AMBIGUITY REPORT,
     never a patch to one side to match the other. The six provisional rows (`ratchet_lambda`,
     `growth_directive`, `overfulfilment_slope`, `penalty_scale`, `effort_cost`, `audit_rate`) stay
     at their placeholders here; gate G1 replaces them from the DP regime map, recorded in
     `runs/G1_decision.md` (PLAN sections 5, 13).

  Edge cases and traps.
    - `price_lag` defaults to `float("inf")` and is the reason the `"inf"` encoding exists. Round
      trip it: `load_config` of a document produced from `hash`'s encoding must reproduce the same
      configuration and the same digest.
    - `input_complementarity` may legitimately be `float("inf")` (the Leontief branch of PLAN
      section 2.6). `inf >= 1`, so the `theta < 1` rejection passes it through - do not add a
      finiteness check.
    - Known tension, to be reported and NOT silently resolved: `validate` rejects a row with
      `sum_k a_jk >= 1`, but the cost-plus price fixed point of PLAN section 2.10 converges only
      when `(1 + m) * sum_k a_jk < 1`. A configuration can therefore pass validation and still make
      `initial_prices` (WO-007) diverge. The rule stated in `spec/spec.py` is the one to implement,
      verbatim. Do not tighten it to include the markup, and do not loosen it. Note the tension in
      your report; if `tests/unit/test_config.py` expects the tighter rule, file an AMBIGUITY REPORT
      and stop.
    - Validation order is unspecified except that the FIRST violation raises. Where the frozen test
      pins an order, follow it; where it does not, any order is acceptable, but each message must
      name its own field.
    - `EnvConfig` is `frozen=True`. Do not memoise the digest by assigning an attribute; if caching
      is wanted, it is a spec change and an AMBIGUITY REPORT, not a local trick.

Forbidden

  - Changing any default, any field name, any field order, any type annotation, or any docstring in
    `gosplan/config.py`. Those are the frozen interface (CONTRACT rule 1) and the registry data
    (CONTRACT rule 11).
  - Adding a field, an arm, a validation rule that the spec does not state, or a `__post_init__`.
  - Editing `gosplan/params.py`, `spec/spec.py`, `CONTRACT.md` or any test.
  - Importing anything outside the standard library plus numpy: no pydantic, no pandas, no PyYAML
    for this loader, no scipy. `hashlib`, `json`, `tomllib` and `dataclasses` are the tools.
  - Importing any module under `gosplan/env/` or `gosplan/agents/`: the configuration layer is
    below them, and a cycle here breaks every later import.
  - Making `validate` return a value, collect warnings, or repair a configuration. It raises or it
    returns `None`.
