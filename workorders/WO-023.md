## Implementation notes

Provisional until the lead revises the spec.

**Locked Phase-2 value (PLAN §4.2, row "5 Hoarding")**, locked *now* and not this card's to change:
`input_holding_loss` `h_X = 0.01`, alongside `alloc_eta_request` `η_q = 0.7` and
`input_complementarity` `θ = 8` (those two are configuration used by WO-030/WO-031, not code here).

**Input holding loss.** PLAN §2.11 fixes the semantics of the own-good loss `h` —
`S ← (1 − h) · S + y`, i.e. applied to carried stock *before* this period's output is added.
Whether `h_X` is applied at the same point of the period schedule, and whether it acts before or
after arrivals are credited, the revision must state.

**Targeted audits.** `p_i = a · (1 + κ_t · downstream_shortfall_i)`, clipped into `[0, 1]`, drawn
through `gosplan.rng.draw(seed_env, "audit", t, i)` as Bernoulli — the same purpose and key
structure as `random`, so common random numbers survive the mode switch. **`κ_t` is not a field of
`InformationConfig` today**: the revision adds it, with a `spec/CHANGELOG.md` entry naming version,
reason and affected work orders, and classifies its arm (INFO) per CONTRACT rule 11. No caller may
assume a value for it before then.

**Soft budget — the open question, and the reason this card is MID-strong.** PLAN §3 defines
`soft_budget` as "bailout probability on `fill < 1`" and nothing else. CONTRACT rule 4 fixes the
reward as exactly `−scale · c_ik` at PRODUCE and `scale · (B(ρ) − 1[audited] · Pen + trade_surplus)`
at REPORT, with no auxiliary term. A bailout therefore **cannot be a new reward term**. The revision
must say which existing quantity it moves — candidates it must choose between, none of which this
card may pick on its own:

- **(a)** a physical top-up of the buyer's input stock `X_bj` when `fill < 1` — a transition rule,
  rule-4 safe, but it changes the conservation identity of T-U1 and must appear in it;
- **(b)** a probability that the target is not ratcheted down, or that `T_min` is relaxed — a
  planner rule, rule-4 safe, keyed only on `PlannerView` quantities per rule 5;
- **(c)** a probability that an assessed penalty is waived — inside the existing `Pen` term, so
  rule-4 safe, but it interacts with the padding elasticity of PLAN §4.5.

Until the revision picks one and states the draw key, implementing any of them is invention.

## Forbidden

- Computing, plotting or testing PLAN §4.1 rows **2, 5, 6, 7** — held out. Row 5 (hoarding) is this
  mechanism's own phenomenon and is computed for the first time in WO-030, inside the P2 acceptance
  run of WO-031 only. Note that T-B3 asserts shortage *propagation* only; the direction of hoarding
  is asserted nowhere, by design.
- Any reward term outside CONTRACT rule 4, and any bailout implemented as a reward bonus.
- Any planner function taking a `State` other than `make_planner_view` (rule 5); the targeted audit
  may key only on `PlannerView.downstream_shortfall`, never on true stock.
- Any rule that makes an enterprise request more inputs, or hold them longer. Hoarding must be a
  consequence of the allocation weights and of `h_X` (rule 7).
- Direct `numpy.random` / `jax.random` under `gosplan/env/` (rule 9).
- Changing the PLAN §4.2 locked values, or folding `audit_rate` / `audit_noise` into the C_OGAS
  contrast (PLAN §4.3: dual-classified, always reported separately).
