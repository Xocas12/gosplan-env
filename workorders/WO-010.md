Implementation notes

  1. `Agent` PROTOCOL. `act(self, obs: Array, phase: Phase, rng: np.random.Generator) ->
     EnterpriseAction` and `reset(self) -> None`. Structural typing: the heuristics and the PPO
     adapter (WO-017) satisfy it without inheriting from it. `obs` is `(N, d)` with the layout of
     `obs_spec(cfg)` and is the ONLY environment input an agent gets.

  2. `Random`. Uniform over `active_action_dims(cfg)` inside the boxes of `action_spec(cfg)`;
     inactive dimensions zero. Draws come from the PASSED `rng` (the `seed_policy` stream), never
     from a module-level generator and never from `gosplan.rng.draw`, which is the environment
     stream (rule 9).

  3. `TruthfulMyopic` - the reference line, verbatim from PLAN section 6.1 and this card:

         PRODUCE step k:  e_ik  = clip(T_i / (A_{s(i)} * cap_i), 0, 1)
         REPORT step:     rho_i = S_i / T_i              # truthful of STOCK, not of this period's y
                          input_request_ij = need_ij     # exactly need
                          trade_offer_ij   = 0           # never trades

     Why that effort: intended step output is `y_hat_ik = (A * cap / M) * e_ik` (section 2.6) and
     the yield shock has mean 1, so uniform effort `e = T / (A * cap)` over the `M` steps gives
     `E[sum_k y_ik] = T` at full coverage. In observation terms the same number is
     `clip(cfg.tech.initial_target_frac * exp(obs[i, 2]), 0, 1)`, because
     `T_0 = initial_target_frac * A * cap` cancels productivity and capacity.

     Why the report is of stock: the audit compares the claim to stock on hand (section 2.8), so
     "truthful" is defined against `S_i` after this period's holding loss and output; `S_i / T_i` is
     observation field 5 directly. Clip the report to `[0, cfg.tech.report_max_ratio]`.

     THIS AGENT MUST CARRY NO BEHAVIOURAL SLACK OF ITS OWN. Every held-out phenomenon of PLAN
     section 4.1 is defined as an excess OVER this agent under common random numbers (rows 2, 5, 6),
     so it never over-produces, never banks, never inflates a request and never trades. It is
     deterministic: T-B1 compares reports with stock to 1e-9, and the CRN comparisons subtract its
     trajectory from a learned one under the same `seed_env`.

  4. `Padder` - `rho = 1` always, effort 0.3 at every PRODUCE step (`PADDER_EFFORT`). SANITY PROBE
     ONLY: it exists to exercise the shortage channel of section 2.7.3 in the MC sanity harness
     (WO-012) and is never a baseline and never appears in a headline table.

  5. `DPGreedy` - holds `cfg` and an ALREADY-SOLVED `DPSolution` and looks the tabulated policy up
     at each enterprise's own `(T_i, S_i)`, reconstructed from observation fields 2 and 5, on the
     DP's own grids (`T` log-spaced on `[T_min, grid.target_hi_mult * A * cap]` with `grid.n_target`
     points; `S` linear on `[0, cfg.tech.inventory_cap_mult * cap]` with `grid.n_stock` points).

     NEAREST GRID POINT, NO INTERPOLATION. PLAN section 5 fixes the grids but no interpolation
     scheme, and "applies the DP policy" is only well defined as the tabulated policy; this is what
     makes WO-014's must-pass item ("`DPGreedy` reproduces the DP policy inside the env at N = 1")
     checkable, since at a state sitting on a grid point the action must equal the table entry
     exactly. A different rule (bilinear interpolation, say) is a spec question, not an
     implementer's choice (rules 1 and 3).

     Check `solution.config_hash == cfg.hash()` before the first `act`: a policy table read against
     a different target grid is silently wrong. Requests are exactly need, as `TruthfulMyopic`'s;
     the DP has no input dimension. Under a Phase-2 configuration with `alloc_eta_request > 0` the
     DP supplies no request policy at all, and using this agent there needs an AMBIGUITY REPORT.
     The single DP effort per period is applied unchanged at each of the `M` PRODUCE steps - uniform
     effort is what the DP assumes and what the cost `M * kappa * e**2` prices.

  6. PHASE MASKING. At a PRODUCE step fill `effort`; at the REPORT step fill `report_ratio` and
     `input_request`. Everything else zero. The environment ignores irrelevant dimensions anyway
     (section 2.3), but filling them is still wrong here: T-B1 reads `trade_offer` and the request
     field.
