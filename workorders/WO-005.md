Implementation notes

  Two bodies. Both formulas are PLAN section 2.6 verbatim; transcribe, do not re-derive.

  1. `coverage(X, need, weights, theta) -> H`. Takes `X` (N, J) input stocks on hand, `need` (N, J)
     this step's input need, `weights` (N, J) with `omega_j = a_{s(i)j} / sum_j a_{s(i)j}`, and the
     complementarity exponent `theta`. Returns `H` (N,) in [0, 1].

         H_ik = ( sum_j omega_j * min(1, X_ij / need_ikj)**(-theta) )**(-1/theta)
         H_ik = 1                        if enterprise i requires no inputs

     Edge cases, all of which must be handled explicitly rather than by an epsilon:
       - `need_ikj == 0` contributes a coverage ratio of 1. Not a division by zero, not a NaN, not
         a 0. A good that is not needed is fully covered by definition, and the same convention
         holds in the observation builder (WO-008).
       - a whole row of `a` equal to zero gives `H = 1` for that enterprise.
       - `theta = float("inf")` takes the `min` branch: `np.min` over the goods with POSITIVE need
         only. Do not compute the CES expression with a huge finite theta as a stand-in.
       - a coverage ratio of exactly 0 with finite `theta` sends `0**(-theta)` to infinity and the
         whole aggregator to `H = 0`. That is the correct value; produce it without emitting a
         numpy warning, e.g. by handling the zero-ratio case before the power.
       - `theta -> 1` reduces to the weighted harmonic mean of the clipped ratios; T-U7 checks it,
         so no special-casing is needed, only correctness at `theta = 1`.

  2. `produce_step(state, action, cfg) -> (state, y_ik, c_ik)`. One PRODUCE step `k` for all `N`
     enterprises, in this order:

         y_hat_ik   = (A_{s(i)} * cap_i / M) * e_ik           # M = cfg.incentive.steps_per_period
         need_ikj   = a_{s(i)j} * y_hat_ik                    # for each good j with a_{s(i)j} > 0
         H_ik       = coverage(X, need, omega, theta)
         eps_ik     ~ LogNormal(-sigma_{s(i)}**2 / 2, sigma_{s(i)})        # mean exactly 1
                      key = (seed_env, "yield", t, k, i)
         y_tilde_ik = y_hat_ik * H_ik * eps_ik
         y_ik       = y_tilde_ik * (1 - v_ik)                 # v = invest fraction; Phase 1 v == 0
         X_ij      -= min(X_ij, a_{s(i)j} * y_tilde_ik)       # consumed against y_tilde, capped
         c_ik       = kappa * e_ik**2 + F * 1[e_ik > 0] + kappa_q * q_ik * e_ik

     Details that are easy to get wrong and are individually tested:
       - INPUTS ARE CONSUMED AGAINST `y_tilde`, the output BEFORE the investment diversion, not
         against `y`. This is what makes the conservation identity T-U1 close.
       - The consumption is CAPPED AT THE STOCK ON HAND: `min(X_ij, a * y_tilde)`, so `X` never
         goes negative even when the coverage aggregator has already accounted for scarcity.
       - The yield shock is drawn with `mean_log = -sigma**2 / 2` so that `E[eps] = 1`; the sigma is
         the SECTOR's, `cfg.supply.yield_sigma[sector_of[i]]`, and the tuple is heteroskedastic by
         design. Draw one `(N,)` vector per step from the single key `(seed_env, "yield", t, k)` -
         the trailing enterprise index is what `shape` vectorises over.
       - Phase-1 constants: `F = cfg.supply.setup_cost = 0.0` and
         `kappa_q = cfg.supply.quality_cost = 0.0`, so the cost is `kappa * e**2` in practice - but
         write all three terms, because the toggles are Phase-2 treatment variables.
       - `cum_output` accumulates `y_ik` and `cum_cost` accumulates `c_ik`; both reset per period,
         and the reset belongs to the step machine (WO-009), not here.
       - `pending_invest` receives `y_tilde_ik * v_ik` in Phase 2; in Phase 1 `v == 0` and the
         column is written with zeros rather than skipped.

     Phase-2 toggles that route through this function and are all off in Phase 1. Implement the
     branch where PLAN section 2.6 states it and leave it inert; do not invent behaviour beyond
     what is written there: setup cost `F`; increasing returns
     `A_j(Kap) = A_j * (Kap / Kap_0)**alpha_irs`; capital accumulation
     `Kap_{t+1} = (1 - dep) * Kap_t + matured investment`; I-O drift `a <- a * exp(zeta)`,
     `zeta ~ N(0, sigma_drift**2)`, with `State.planner_io` held FIXED so the planner's picture goes
     stale; quality routed through the bundle (`X_ij` credited as `deliv * qbar_j`); non-uniform
     `delivery_timing`, under which a delivered unit arrives at step
     `k ~ Categorical(arrival_probs)` drawn with purpose `arrival`. Anything PLAN section 2.6 does
     not state about these branches is an
     AMBIGUITY REPORT, not a decision.
